# AI Museum of the Future

An AI-powered virtual museum that represents our current era as if curated 100 years from now. The system collects public contemporary data, analyzes it through specialized AI agents, grounds findings in a RAG knowledge base, and synthesizes a coherent virtual exhibition.

**Central question:** *If a museum were created in 100 years to represent our time, what would it preserve, and how would it tell our story?*

Course project — Esprit 2026-2027, 5DS, Advanced Deep Learning ("AI Automation" final project). See [docs/](docs/) for the full assignment brief, Week 1 use case/scope writeup, and current architecture diagram.

## Architecture

The pipeline has six layers, orchestrated end-to-end by n8n (no manual cell-by-cell execution):

1. **Public data layer** (`data/`) — collect contemporary textual, visual and structured information (news, science, tech, culture, images) from accessible public sources (GDELT, NewsAPI, Wikimedia Commons, arXiv, Google Trends, Wikipedia/Wikidata, ...).
2. **n8n orchestration** (`n8n/`) — trigger (manual / webhook / scheduled), fetch, preprocess, store, route information between steps and agents, generate final output.
3. **Knowledge layer / RAG** (`rag/`) — chunk documents, embed, store in a vector DB, retrieve relevant context (top-k, filters, optional reranking).
4. **Multimodal layer** (`multimodal/`) — image understanding (object detection, scene analysis, visual description) combined with text and metadata.
5. **Specialized agents** (`agents/`) — Socio-Historical, Science & Technology, Culture & Media, and Vision agents examine the same evidence from complementary perspectives, cross-validating through a shared communication layer; an Orchestrator (n8n + LLM Curator) synthesizes their findings into a coherent exhibition.
6. **Final output** — a virtual exhibition: title & concept, 4–6 sections, selected items/artifacts, context & descriptions, connected narrative, visual presentation.

## Setup and run (from a fresh clone)

Requires Python 3.11+.

```bash
git clone <repo-url> && cd AI-Museum-of-the-future
python -m venv .venv
.venv\Scriptsctivate            # Windows   (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt
cp .env.example .env              # Windows: copy .env.example .env
```

Then fill in `.env` (**never commit it**). What you need depends on what you want to run:

| You want to... | Keys needed |
|---|---|
| Run the agents / curator (`test_agents_live.py`) | `LLM_API_KEY` only (free, see below) |
| Image analysis, retrieval reranking | `LLM_API_KEY` (same free key) |
| Run the web app and the tests | nothing |
| Fetch + ingest data into the vector store | Supabase keys (embeddings are local, no key) |

**No OpenAI account is needed anywhere.** Chat, vision and reranking go through the Groq key; embeddings run locally with [fastembed](https://github.com/qdrant/fastembed) (`paraphrase-multilingual-MiniLM-L12-v2`, 384 dimensions, multilingual). The first embedding call downloads a ~120 MB model once.

### 1. LLM provider for the agents (free)

All agents (historian, sociologist, technology, culture_art, visual and the curator) use any **OpenAI-compatible** endpoint. The default is [Groq](https://console.groq.com/keys), which has a free tier:

1. Create a free account at https://console.groq.com/keys and generate an API key.
2. Put it in `.env`: `LLM_API_KEY=gsk_...` (each teammate uses their own key).
3. Defaults are `LLM_BASE_URL=https://api.groq.com/openai/v1` and `LLM_MODEL=openai/gpt-oss-120b`. Override them in `.env` only if needed. Model availability depends on your account: list yours with
   `python -c "from dotenv import load_dotenv; load_dotenv(); from agents.llm_config import build_llm_client as b; print([m.id for m in b().models.list().data])"`.
4. Optional: `CURATOR_MODEL=<model>` uses a different model for the curator only.

Other free options (set `LLM_BASE_URL` + `LLM_MODEL`): Google Gemini `https://generativelanguage.googleapis.com/v1beta/openai/` (`gemini-2.0-flash`), OpenRouter `https://openrouter.ai/api/v1` (a `:free` model). Config lives in [`agents/llm_config.py`](agents/llm_config.py).

Test the agents and the full pipeline live:

```bash
python test_agents_live.py        # Windows: set PYTHONIOENCODING=utf-8 first, or the console crashes on non-ASCII output
```

### 4. Data and vector store (optional, only for the RAG part)

1. Start with the keyless sources (GDELT, Wikimedia Commons, arXiv, World Bank, Wikipedia/Wikidata). Only add `NEWSAPI_KEY` / `UNSPLASH_ACCESS_KEY` / `NASA_API_KEY` if you need those sources.
2. Create a free [Supabase](https://supabase.com) project, put its URL/keys in `.env`, then run [`rag/schema.sql`](rag/schema.sql) (Dashboard > SQL Editor > New query, or `psql "$SUPABASE_DB_URL" -f rag/schema.sql`). It enables `pgvector` and creates the `documents`/`chunks` tables plus a `match_chunks` function. Supabase also has a native n8n node.
   - For `SUPABASE_DB_URL`, use the **Transaction pooler** string (Settings > Database > Connection string, port 6543). The direct `db.<ref>.supabase.co` host is IPv6-only and won't resolve on most networks.
3. Embeddings are local and the vector columns are `vector(384)`. If your Supabase project was created with the old OpenAI schema (1536 dims), drop the `chunks` table, its index and `match_chunks`, re-run `rag/schema.sql`, then re-ingest. Never mix vectors from different embedding models in one table.
4. Fetch, normalize and ingest: `python data/fetch_all.py` (`--sources gdelt`, `--skip-process`, `--skip-ingest` available). Scripts load config via `scripts/config.py`.

All specialists share one design ([`agents/base_agent.py`](agents/base_agent.py)); each only declares its focus, its own search queries and its prompt:

- **Own search.** Besides the evidence passed to the pipeline, each agent searches the knowledge base with its own queries through the hybrid retriever (below). The sociologist uses HyDE for this, the visual agent searches image records.
- **Evidence lines** read `[chunk_id] (year · source/category · title) text`.
- **Citations per finding.** Every finding must cite at least one `[chunk_id]`, and every ID it cites must be in its evidence; other findings are dropped. A shortened UUID (`[71108630]`) is resolved to the full ID when unambiguous. With nothing cited left the agent abstains, and the curator lists it in `missing_perspectives`. Provider errors raise and are reported the same way.
- **Visual agent** runs the vision model on up to `VISUAL_MAX_IMAGES` (default 3) images in its evidence and works from those descriptions.

### Pipeline

```
specialists (parallel, own search)  ->  peer review  ->  curator  ->  fact-check (-> one curator rewrite)
```

- **Peer review** ([`agents/reviewer.py`](agents/reviewer.py)): one LLM call reads all insights and reports agreements, tensions and weak findings; the curator uses them.
- **Curator** narratives cite `[chunk_id]` too, only IDs the specialists cited; it receives the text behind each ID.
- **Fact-check** ([`agents/fact_checker.py`](agents/fact_checker.py)) compares each narrative with its cited evidence; unsupported claims go back to the curator once, and the final verdicts are in `ExhibitionSynthesis.fact_check`.

Run the whole system on the knowledge base (Tunisia 2020-2026 by default) and save the run:

```bash
python run_exhibition.py                    # --country "" for no country filter, --rerank, --no-review, --no-fact-check
python -m evaluation.evaluate_run --latest --judge
```

Each run is saved to `runs/<run_id>/run.json` (git-ignored): evidence per agent, every prompt and response, insights, review, exhibition, fact-check and timings.

### Hybrid search

[`rag/vector_store/hybrid_retriever.py`](rag/vector_store/hybrid_retriever.py) fuses vector search (`match_chunks`) with Postgres full-text search, so exact names ("Saïed", "Startup Act") are found; joins each chunk to its document (title, year, url, image); filters by year range, country mention and category; down-weights statistics rows and keeps at most one; keeps one chunk per document and drops near-duplicates; and can LLM-rerank. When a country filter leaves too few results, it tops up with results from elsewhere, marked "outside the requested country" (the corpus has little Tunisian technology, image or culture material). `rag/schema.sql` has an optional full-text index; run it in Supabase to make keyword search faster.

### Quality evaluation

See [`evaluation/README.md`](evaluation/README.md). Retrieval on 16 test queries (k=5):

| method | precision@5 | hit@5 | MRR | statistics share |
|---|---|---|---|---|
| vector (before) | 0.41 | 0.75 | 0.52 | 0.11 |
| hybrid | 0.68 | 0.94 | 0.83 | 0.00 |
| hybrid + LLM rerank | 0.72 | 1.00 | 0.92 | 0.00 |

### Speed and cost settings

| Variable | Default | Effect |
|---|---|---|
| `LLM_MAX_CONCURRENCY` | 3 | concurrent LLM calls across agents (free tiers limit tokens per minute) |
| `LLM_CACHE_DIR` | unset | cache identical LLM calls on disk (reproducible, free evaluation re-runs) |
| `HYDE_CACHE_DIR` | `.cache/hyde` | cache of the sociologist's hypothetical documents (`""` disables) |
| `VISUAL_MAX_IMAGES` | 3 | images the visual agent sends to the vision model |

Retries wait as long as the provider asks, but stop at once on long waits such as a daily token limit. A full run makes about 15-20 LLM calls; on Groq's free tier (200k tokens per day per model) that is a few runs per day.

## Curator agent

[`agents/curator.py`](agents/curator.py) takes the five specialist insights plus their cross-references and writes the exhibition (title, concept, 4-6 sections, selected items). Prompt: [`prompts/curator.md`](prompts/curator.md) (v5: bilingual English/French because the historian reports in French; cited narratives; uses the peer review).

What changed in the latest iteration:

- **Retry with feedback.** If the output breaks a rule (section count outside 4-6, empty title/narrative, missing title/concept), the curator retries once, telling the model exactly what was wrong. It raises `CuratorValidationError` only if the second attempt also fails.
- **No invented artifacts.** `selected_items` and each section's new `artifacts` list are checked against the artifacts the specialists actually selected. If nothing valid remains it falls back to the cross-references.
- **Failed specialists are visible.** Empty insights (an agent that timed out or errored) are passed to the model as `unavailable_perspectives` and returned in the new `ExhibitionSynthesis.missing_perspectives` field.
- **Better synthesis prompt.** Builds the exhibition around artifacts that several specialists picked, surfaces disagreements between perspectives, imposes a narrative arc and 60-120 word narratives, and forbids invented facts. A dedicated system prompt sets the curator persona.
- **Changelog stripped.** The version-history header in `curator.md` is no longer sent to the model.
- **Free LLM provider.** The agents moved from `gpt-4o-mini` to the configurable OpenAI-compatible provider above (Groq by default), with an optional separate `CURATOR_MODEL`.
- **OpenAI removed repo-wide.** Image analysis uses a Groq vision model (`VISION_MODEL`, default `qwen/qwen3.8-27b`), reranking uses `RERANK_MODEL` (defaults to `LLM_MODEL`), and embeddings are local (`rag/vector_store/local_embeddings.py`).

Tests: [`tests/agents/test_curator_improvements.py`](tests/agents/test_curator_improvements.py) covers retry, artifact validation, missing perspectives and header stripping.
