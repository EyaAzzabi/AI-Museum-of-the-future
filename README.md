# AI Museum of the Future

An AI-powered virtual museum that represents our current era as if curated 100 years from now. The system collects public contemporary data, analyzes it through specialized AI agents, grounds findings in a RAG knowledge base, and synthesizes a coherent virtual exhibition.

**Central question:** *If a museum were created in 100 years to represent our time, what would it preserve, and how would it tell our story?*

Course project — Esprit 2026-2027, 5DS, Advanced Deep Learning ("AI Automation" final project). See [docs/](docs/) for the full assignment brief and Week 1 use case / scope / architecture writeup.

## Architecture

The pipeline has six layers, orchestrated end-to-end by n8n (no manual cell-by-cell execution):

1. **Public data layer** (`data/`) — collect contemporary textual, visual and structured information (news, science, tech, culture, images) from accessible public sources (GDELT, NewsAPI, Wikimedia Commons, arXiv, Google Trends, Wikipedia/Wikidata, ...).
2. **n8n orchestration** (`n8n/`) — trigger (manual / webhook / scheduled), fetch, preprocess, store, route information between steps and agents, generate final output.
3. **Knowledge layer / RAG** (`rag/`) — chunk documents, embed, store in a vector DB, retrieve relevant context (top-k, filters, optional reranking).
4. **Multimodal layer** (`multimodal/`) — image understanding (object detection, scene analysis, visual description) combined with text and metadata.
5. **Specialized agents** (`agents/`) — Historian, Sociologist, Technology, Culture & Art, and Visual agents examine the same evidence from complementary perspectives; a Curator agent synthesizes their findings into a coherent exhibition.
6. **Final output** — a virtual exhibition: title & concept, 4–6 sections, selected items/artifacts, context & descriptions, connected narrative, visual presentation.

## Repository structure

```
data/            Public data collection & preprocessing
  raw/           Unprocessed pulls from source APIs
  processed/     Cleaned, normalized, structured data
rag/             Knowledge base: chunking, embeddings, vector store, retrieval
  chunking/      Chunking strategies (fixed / semantic / recursive)
  vector_store/  Vector DB artifacts (not committed)
agents/          Specialized agents + curator, orchestration/communication logic
multimodal/      Image understanding & multimodal embeddings
  images/        Local image assets used/generated by the pipeline
prompts/         Versioned prompt library (one file per prompt, with iteration history)
n8n/             Exported n8n workflow(s) (JSON) and setup instructions
scripts/         One-off / utility scripts
docs/            Assignment brief and Week 1 architecture writeup (PDFs)
```

## Setup

1. `pip install -r requirements.txt`
2. `cp .env.example .env` and fill in your own values — **never commit `.env`**.
3. Data source keys: start with the keyless sources first (GDELT, Wikimedia Commons, arXiv, World Bank, Wikipedia/Wikidata) — no signup needed. Only add `NEWSAPI_KEY` / `UNSPLASH_ACCESS_KEY` / `NASA_API_KEY` if you need those specific sources.
4. Vector store: create a free [Supabase](https://supabase.com) project, put its URL/keys in `.env`, then run [`rag/schema.sql`](rag/schema.sql) against it (Dashboard > SQL Editor > New query, or `psql "$SUPABASE_DB_URL" -f rag/schema.sql`) — it enables `pgvector` and creates the `documents`/`chunks` tables plus a `match_chunks` retrieval function. Supabase has a native n8n node, so it also plugs directly into the orchestration layer.
   - For `SUPABASE_DB_URL`, use the **Transaction pooler** connection string (Settings > Database > Connection string, port 6543) — the direct `db.<ref>.supabase.co` host is IPv6-only and won't resolve on most networks/CI runners.
5. Scripts load config via `scripts/config.py` (reads `.env` through `python-dotenv`).
